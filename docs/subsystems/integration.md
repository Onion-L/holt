# Integration view

The Worktrees page: one repository's trunk plus every linked worktree — the read-only branch tree, and the UI-triggered local merge (squash / fast-forward) and worktree deletion. Checks and reviews are later slices; nothing in this surface ever gates a merge on them.

Not here: the agent's git surface stays read-only (no git write ever enters the toolset — ADR-ui-driven-merge-and-worktree-delete); the trunk's commit history rendering belongs to workspace-git; session-worktree *materialization* belongs to workspace-git too.

## Runtime path

1. **Open.** The page renders and picks its repo (first render calls `ensure_started`; a later state change re-runs the pick). `ListIntegration` lands; the first worktree auto-selects; the detail builds with pinned diff panes.
2. **Refresh.** The header's refresh runs `FetchAll` (a fetch failure does not hide the snapshot), then reloads `ListIntegration` and the trunk picker's `ListRefs`. Session-status changes never refetch — the status chips re-derive at render.
3. **Merge.** The bar's button calls `PreviewMerge`. A clean preview opens the confirm dialog seeded with the default message; confirm calls `MergeIntoTrunk` carrying the preview's heads. Success toasts the merged sha and reloads; a refusal shows its label, up to eight detail lines, and the reason's one action (`trunk-checked-out-dirty` → open the main checkout); `stale` re-previews automatically. A conflict swaps the bar for the conflict row — Holt has no merge editor; the author chat resolves.
4. **Delete.** The bar (merged / no-changes / missing) or cleanup asks, the confirm dialog names what goes (dirty adds the data-loss warning and takes `force`), and `DeleteWorktree` removes the worktree and retires a session chat. A later send to the retired chat unarchives it, rematerializes the worktree from the chat's stored spec, rebuilds the `wt-` Space, and re-parents.

## Constraints, state, and failure behavior

- **Nothing gates a merge.** Checks and reviews (later slices) will inform, never block; the bar's hints are the whole policy.
- **No half-merged state survives a failure.** The working tree syncs before the ref moves; a failed `set_target` force-checks HEAD back out over exactly the merge's paths (a safe checkout of the old tree is a no-op — HEAD never moved); every refusal lands before any write except the checked-out-dirty overlap, which refuses before the checkout.
- **The trunk and the main checkout's branch are never deleted with a worktree.** A worktree holding either refuses the whole deletion (directory and registration included).
- **User data is never overwritten.** Overlapping uncommitted changes in the main checkout refuse; non-overlapping ones survive the safe checkout. Dirty worktrees delete only with an explicit force. No stash, no force-push, no push at all.
- **The trunk never moves under another worktree.** A trunk checked out in a linked worktree refuses — git2's ref write would strand that worktree's index and files.
- **`merged` is Holt's own marker, not ancestry.** `refs/holt/merged/<worktree>` equals the branch head; a later branch commit naturally unmerges it. A merge made outside Holt reads as "no changes", which is accepted.
- **The page is read-mostly.** All writes go through the merge bar's buttons; every list interaction is a selection.

## Verification

```sh
cargo test -p holt-engine --test all integration_rpc
cargo test -p holt-ui integration
```

The engine suite covers, against real git repositories: ahead/behind and fork against an independent rev-walk; dirty (untracked yes, ignored no); `merged` from the marker ref with the squash-trailer merge point; manual, missing, and unreadable (chmod'd index) worktrees; the chatId backfill and its removal with the chat; trunk overrides and failures; the non-repo error; the trunk cap. The merge slice: squash's single-parent commit, tree, trailer, and clean main checkout; ff; the stale refusal; same-line conflicts (paths, nothing changed); overlapping dirt refusing byte-identically; non-overlapping dirt surviving; the locked-ref rollback; the trunk-held-elsewhere refusal; the refusal taxonomy; the merged flip and its unmerge; the user-message trailer append. The delete slice: clean removal, dirty force, the session chat's retirement, unregistered names, the running-Turn refusal, and the send-after-retire rematerialization (worktree, branch, Space, chat re-parent, unarchive). The UI suites pin the status derivation, orphan/filter rules, repo selection, the branch-tree row/lane layout, and a window-level test that renders the page, selects worktrees, and drives the whole merge flow (preview → dialog → confirm) through a scripted engine.
