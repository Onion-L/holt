# Integration view

The Worktrees page: one repository's trunk plus every linked worktree — the read-only branch tree, and the UI-triggered local merge (squash / fast-forward) and worktree deletion. Checks and reviews are later slices; nothing in this surface ever gates a merge on them.

Not here: the agent's git surface stays read-only (no git write ever enters the toolset — ADR-ui-driven-merge-and-worktree-delete); the trunk's commit history rendering belongs to workspace-git; session-worktree *materialization* belongs to workspace-git too; checks never gate a merge — they inform the merge bar and nothing else.

## Responsibilities and sources of truth

| Part | Responsibility | Source |
| --- | --- | --- |
| Snapshot | `ListIntegration {repoPath, trunk?}`: the main checkout, the trunk's commits (newest first, capped at 200 with `trunkTruncated`), and every linked worktree — branch/head/fork (`merge-base`), `graph_ahead_behind` counts, dirty (untracked included, ignored excluded, with a file count), `missing` for registered-but-gone or unreadable directories, and `merged` read from `refs/holt/merged/<worktree>` with `mergeSha` resolved from the trunk's `Holt-Merged-From` trailer commit on its first-parent line, up to 5000 deep (ff falls back to the branch head). `defaultTrunk` names the repo's own default branch beside the selected `trunk`; `chatId` is backfilled engine-side when the worktree name matches a chat row. Checks worktrees (paths under `<data dir>/integration/checkouts/`) never list: a live run's checkout is skipped untouched, and a crashed run's leftover registration is pruned on sight (temp branch included). Computed in one pass under the checkout lock; a worktree that fails to read reports `missing`, never fails the call |
| Merge preview | `PreviewMerge {repoPath, worktree, trunk, mode}`: the in-memory squash (three-way `merge_trees`, conflicts as path lists — no conflict state ever lands on disk) or fast-forward (refused while behind), diffed `tree(trunk) → tree` under the shared 3 MiB patch cap, plus the squash default message (chat title or oldest subject, squashed subjects, the trailer). Refusals arrive as `outcome.refused` (`nothing-to-merge`, `ff-not-possible`, `trunk-checked-out-elsewhere`, `worktree-missing`, `branch-detached`), never as errors | `git.rs` (`merge_preview`, `merge_context`, `merged_tree`, `squash_message`) |
| Merge landing | `MergeIntoTrunk {…, message?, expect}`: the whole landing under the checkout lock — heads re-checked against `expect` (`stale`), the squash commit written object-store-only, the main checkout's working tree synced **before** the ref moves (overlapping uncommitted changes refuse as `trunk-checked-out-dirty`), `set_target` on the trunk ref with a `holt: merge <worktree> (<mode>)` reflog, and `refs/holt/merged/<worktree>` written at the branch head. A failed ref update force-checks HEAD back out over exactly the merge's paths. Refusals report through `Failed` whose first line is the stable `merge-refused: <reason>`, one detail per following line | `git.rs` (`merge_into_trunk`), `rpc/git_surface.rs` (`merge_into_trunk`) |
| Worktree deletion | `DeleteWorktree {repoPath, worktree, force?, trunk?}`: refuses a worktree running a Turn and one whose checked-out branch is the selected trunk, the repository's default branch, or the main checkout's own (deleting it would strand the repository — the page hides the delete button for those, mirroring the same set); dirty trees need `force` (the refusal lists what would be lost); removes directory, registration (prune), branch, and merged marker. A session worktree (name matches a chat, or the path sits under `<data dir>/worktrees/`) then retires politely: the chat moves onto the repo's main Space (else Home), the `wt-<chatId>` row drops, the chat is archived — never deleted — and a queued send unarchives it and rematerializes the worktree from the chat's spec | `git.rs` (`remove_worktree`), [`crates/engine/src/rpc/run.rs`](../../crates/engine/src/rpc/run.rs) (`unarchive_if_archived`), `rpc/git_surface.rs` (`delete_worktree`, `retire_session_worktree`) |
| Page | The Worktrees route: repo picker (project spaces, deduped by path; the selected chat's worktree repo wins the default), trunk picker (not persisted), filter chips (non-matching rows dim, never hide — hiding tears the tree), the branch tree (trunk spine, swim lanes, dashed merge-backs, blinking working heads), and the detail pane whose Changes/Commits tabs embed `Changes` panes pinned to the worktree's path. Status is derived per render from the snapshot plus the chats/sessions watches — never stored | [`crates/ui/src/integration.rs`](../../crates/ui/src/integration.rs), [`integration/graph.rs`](../../crates/ui/src/integration/graph.rs), [`integration/detail.rs`](../../crates/ui/src/integration/detail.rs) |
| Local checks | The trunk's `.holt/checks.toml` (read from the trunk HEAD tree — never the working tree, so a branch cannot edit its own rules; unknown fields are errors) executed against the worktree's in-memory squash merge in a throwaway worktree under `<data dir>/integration/checkouts/<runId>/`. `RunChecks` starts one run per (repo, worktree) — a new run stops the previous — and `WatchChecks` streams the latest run (or `null`), stamping `stale` at watch time by re-reading both heads. Checks run serially with `CI=true`, the same shell and process-group rules as agent commands, TERM → grace → KILL on timeout or `StopChecks`; the checkout is pruned after the run and at boot. The latest result persists per (checkout key, worktree) under `integration/checks/`; logs live only in memory (`SubscribeCheckLog` streams them; a restart leaves the persisted `logTail`) | [`crates/engine/src/integration_checks.rs`](../../crates/engine/src/integration_checks.rs), `git.rs` (`checks_config_blob`, `checks_merge_tree`, `checkout_detached_tree`), [`crates/engine/src/rpc/integration.rs`](../../crates/engine/src/rpc/integration.rs), types in [`crates/rpc/src/checks.rs`](../../crates/rpc/src/checks.rs) |
| Merge bar | The detail's footer per derived status: working (disabled), dirty (mergeable — only committed work merges), behind (squash only), ready (mode toggle), merged / no-changes / missing (delete or cleanup). The merge click previews, a confirm dialog (mode, stats, main-checkout state, editable message, fold-out final diff) confirms with the previewed heads; conflicts offer "open in editor" and "hand back to chat" (an editable instruction queued into the author chat via `QueueCommand`); `stale` auto re-previews | `integration.rs` (`render_merge_bar`, `MergeFlow`) |

## Runtime path

1. **Open.** The page renders and picks its repo (first render calls `ensure_started`; a later state change re-runs the pick). `ListIntegration` lands; the first worktree auto-selects; the detail builds with pinned diff panes.
2. **Refresh.** The header's refresh runs `FetchAll` (a fetch failure does not hide the snapshot), then reloads `ListIntegration` and the trunk picker's `ListRefs`. Session-status changes never refetch — the status chips re-derive at render.
3. **Merge.** The bar's button calls `PreviewMerge`. A clean preview opens the confirm dialog seeded with the default message; confirm calls `MergeIntoTrunk` carrying the preview's heads. Success toasts the merged sha and reloads; a refusal shows its label, up to eight detail lines, and the reason's one action (`trunk-checked-out-dirty` → open the main checkout); `stale` re-previews automatically. A conflict swaps the bar for the conflict row — Holt has no merge editor; the author chat resolves.
4. **Check.** The checks card (overview and review tabs) watches the latest run for the selected worktree; 运行 starts a fresh one. A stale run greys the card; a conflicting merge preview or an invalid `checks.toml` shows as the run's error without running anything. The commands come from the trunk — the user's own repo config, trusted like a terminal command, never permission-gated.
5. **Delete.** The bar (merged / no-changes / missing) or cleanup asks, the confirm dialog names what goes (dirty adds the data-loss warning and takes `force`), and `DeleteWorktree` removes the worktree and retires a session chat. A later send to the retired chat unarchives it, rematerializes the worktree from the chat's stored spec, rebuilds the `wt-` Space, and re-parents.

## Constraints, state, and failure behavior

- **Nothing gates a merge.** Checks and reviews (later slices) will inform, never block; the bar's hints are the whole policy.
- **No half-merged state survives a failure.** The working tree syncs before the ref moves; a failed `set_target` force-checks HEAD back out over exactly the merge's paths (a safe checkout of the old tree is a no-op — HEAD never moved); every refusal lands before any write except the checked-out-dirty overlap, which refuses before the checkout.
- **The trunk and the main checkout's branch are never deleted with a worktree.** A worktree holding either refuses the whole deletion (directory and registration included).
- **User data is never overwritten.** Overlapping uncommitted changes in the main checkout refuse; non-overlapping ones survive the safe checkout. Dirty worktrees delete only with an explicit force. No stash, no force-push, no push at all.
- **The trunk never moves under another worktree.** A trunk checked out in a linked worktree refuses — git2's ref write would strand that worktree's index and files.
- **`merged` is Holt's own marker, not ancestry.** `refs/holt/merged/<worktree>` equals the branch head; a later branch commit naturally unmerges it. A merge made outside Holt reads as "no changes", which is accepted.
- **The page is read-mostly.** All writes go through the merge bar's buttons; every list interaction is a selection.
- **Checks execute the repository's own commands** (`.holt/checks.toml` from the trunk) with the same trust as a user-typed shell command — no permission gate; the merge bar treats their outcome as a hint only.
- **One run per (repo, worktree)**; a new `RunChecks` stops the old. A run's throwaway checkout lives exactly as long as the run.

## Verification

```sh
cargo test -p holt-engine --test all integration_rpc
cargo test -p holt-engine --test all integration_checks_rpc
cargo test -p holt-ui integration
```

The engine suite covers, against real git repositories: ahead/behind and fork against an independent rev-walk; dirty (untracked yes, ignored no); `merged` from the marker ref with the squash-trailer merge point; manual, missing, and unreadable (chmod'd index) worktrees; the chatId backfill and its removal with the chat; trunk overrides and failures; the non-repo error; the trunk cap. The merge slice: squash's single-parent commit, tree, trailer, and clean main checkout; ff; the stale refusal; same-line conflicts (paths, nothing changed); overlapping dirt refusing byte-identically; non-overlapping dirt surviving; the locked-ref rollback; the trunk-held-elsewhere refusal; the refusal taxonomy; the merged flip and its unmerge; the user-message trailer append. The delete slice: clean removal, dirty force, the session chat's retirement, unregistered names, the running-Turn refusal, and the send-after-retire rematerialization (worktree, branch, Space, chat re-parent, unarchive). The checks suite covers, with real shells: the run executing in a checkout of the merged tree (the branch's file, the trunk's file, and the trunk's config all present; HEAD is neither head); passed/failed rows with exit codes; the timeout kill (the process-group record is reaped, unix); `StopChecks` marking rows stopped and cleaning the checkout; a conflicting preview erroring the run before any command; a moved trunk marking the persisted run stale at watch time; no config meaning a `null` watch and a failed run; and unknown config fields rejecting the run. The UI suites pin the status derivation, orphan/filter rules, repo selection, the branch-tree row/lane layout, and a window-level test that renders the page, selects worktrees, and drives the whole merge flow (preview → dialog → confirm) through a scripted engine.
