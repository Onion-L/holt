# Conversation policy

The user-facing rules of a chat's queue and its side tasks: how work is admitted (FIFO with priority and attended-send exceptions), what steer, edit-last, and rewind do to the conversation, when compaction runs, the one-shot title task, and the agent's question card. These are the policies a user feels; the loop's streaming and retry mechanics they ride belong to run-loop, the durable records to persistence.

Not here: the agent loop and Turn execution pipeline (see run-loop); the permission gate that pauses a Turn mid-run (see permission-gate); goals and routines, which enqueue through these same rules (see goals-routines).

## Responsibilities and sources of truth

| Part | Responsibility | Source |
| --- | --- | --- |
| Queue semantics | One FIFO consumer and one execution lock per chat, held through preparation, execution, History repair, transcript settlement, and queue completion. Execution failures pause remaining work; admission failures (missing credentials, an unresolved skill) retain the head with an error and create no Turn; an interrupt cancels and pauses, and the channel stays occupied until cleanup completes | [`crates/engine/src/queue.rs`](../../crates/engine/src/queue.rs) |
| Admission checkpoint | Pending→started is atomically replaced and synced before any model or tool work; mutations serialize with admission on the queue lock, so an edit landing between the consumer's pick and the checkpoint wins and a delete simply removes the item. After the checkpoint the item is execution's property — mutations fail with an already-executing error and the run proceeds exactly once | `queue.rs` |
| Steer | The explicit priority action: with a message id it promotes that pending item; without, it enqueues the new prompt ahead of parked work; either way it cancels the running Turn, waits for cleanup, unpauses, and starts. Pending steer requests keep their submission order; Run-now on a paused queue authorizes only the selected item | [`crates/engine/src/rpc/run.rs`](../../crates/engine/src/rpc/run.rs) |
| Attended send | The one exception to pause: a first acceptance arriving while the channel is settled and the queue paused is admitted at once through a one-shot, persisted grant bound to its message id — it runs alone ahead of parked work, and the queue returns to its pause when it settles. Continue lifts the single-run scope; deleting the last pending item (nothing executing, no queue error) clears the pause | `queue.rs` (`attended_grant`) |
| Edit-last | Applies only to the latest user transcript entry: cancels the active Turn, prunes that Turn's later transcript and History, preserves the message identity, and queues a replacement ahead of remaining work using the chat's current settings. Existing workspace side effects and usage remain; a stale message id is rejected | `rpc/run.rs` (`edit_last_message`) |
| Rewind to a message | `RewindToMessage` on a user message (ADR-rewind-to-a-message-is-all-or-nothing): that message, its Turn, and everything after leave the conversation, and every file those Turns changed goes back to its bytes before the first of them, from the step checkpoints (see workspace-git). The plan is read-only — a Turn still running keeps running while the dialog is open, and its reply sizes both the cut (`turns`, `steps`) and the confirm's side effects (`willStopTurn`, `pendingCount`, `workflowsToStop`, `runningProcesses`) for the dialog; while a Turn runs the conflict verdict is provisional (the run's own writes read as Changed), so the plan clears conflicts and the confirm's re-derivation is the verdict. A message a preparation failure left in the transcript without a History entry still cuts — the History keeps its prefix; only a compaction's summary standing in for the target refuses, with its own reason. Any file that moved on, was never stored, or would leave the work tree refuses the whole plan — nothing is written and nothing is staged (a failed plan clears an earlier staged one). A clean plan is staged in the engine, in memory per chat (a restart forgets it; a newer plan replaces it). `ConfirmRewind` interrupts the running Turn and waits out its settle (bounded at 10s — a Turn that never settles refuses with the interrupt's park lifted again), then re-derives the plan against post-stop state — a refusal or a new conflict changes nothing but that park (lifted, unless the user had paused the queue themselves) and the dialog re-opens; the queued prompts and the cut Turns' workflows die with the apply, never with a refusal. The apply stops the workflow runs the cut Turns launched (their handle is a call the kept History no longer holds), sweeps every queued item (the pause self-clears with them as the last delete does), and is written down whole and synced (`checkpoints/{chatId}/rewind.json`) and carried out — files, the step log dropping the undone steps, History, transcript, the cut Turns' change sets — every part idempotent, so a crash part-way is finished by the chat's next load, as is a record the retired step-cut build wrote (under that build's own cut). The chat stays idle; usage remains. Refused for a message no longer in the conversation, a message a compaction summarized away (its own reason), a non-user message, a message older than the checkpoints this chat keeps, a work tree that can no longer be discovered while steps exist (the change-set surface's stable non-Git phrase), and a confirm with no staged plan | `rpc/run.rs` (`rewind_to_message`, `confirm_rewind`), [`rewind.rs`](../../crates/engine/src/rewind.rs) |
| Compaction | Shrinks the History into a model-written summary plus a verbatim recent tail. Three triggers: automatically before a Turn and between tool rounds, manually via `/compact` (a typed queue item sharing the channel — never a Turn), and on context overflow (compact and continue the same Turn, once; a second overflow flags the chat and the next Turn compacts unconditionally first). Upstream defaults: a context reserve, a recent-tokens tail, an estimator anchored on the last real usage, and a cut point that never separates a tool call from its result | [`crates/engine/src/compaction.rs`](../../crates/engine/src/compaction.rs) |
| Title task | One independent background request on a chat's first accepted prompt — outside the Turn lifecycle: its own token (only chat deletion cancels), no Session status, no History/transcript footprint, no retries, billed immediately as `title`. Every failure is silent and keeps the first-line fallback; the prompt frames the first message as material to name, never a message to answer | [`crates/engine/src/title_task.rs`](../../crates/engine/src/title_task.rs) |
| Question card | `ask_user` never waits: it lands a `QuestionCard` part and returns, and the model stops its Turn. `SettleQuestion` stamps the card under the transcript lock and enqueues each question restated with its answer as an ordinary user message (a failed enqueue rolls the stamp back); `DismissQuestion` stamps it superseded, persistently — a restart does not resurrect it. Any new Turn retires still-pending cards; Plan and Provider Turns mount no `ask_user` | [`crates/engine/src/tools/ask_user.rs`](../../crates/engine/src/tools/ask_user.rs) |
| UI cutaways | The composer's queue rows (edit/delete/run-now per kind), the approval bar's question pages with their `1/N` pager, the compacted-transcript dividers, and the user row's hover rewind affordance (main-chat committed rows only — available while the chat works too, since only the confirm stops the Turn): a staged plan in a confirm dialog whose lines come from the reply itself (the cut's size, the steps undone, the stop, the queued messages deleted, the workflows stopped by name, the background processes left running), that cannot be confirmed while a conflict stands, and an applied rewind that returns the cut message to the composer losslessly — body in the input, attachment trailers back as staged chips — as a refill of an empty draft on that chat | [`crates/ui/src/composer/queue.rs`](../../crates/ui/src/composer/queue.rs), [`approval_bar.rs`](../../crates/ui/src/composer/approval_bar.rs), [`rewind.rs`](../../crates/ui/src/rewind.rs) |

## Runtime path

1. **Accept.** A submission lands in the durable queue (model and reasoning captured at submission) and the watch frame carries the snapshot.
2. **Admit.** The consumer picks the head, writes the checkpoint, snapshots permission mode and live checkout identity, and refreshes the Turn's diff baseline — then the run loop owns the Turn.
3. **Settle.** History repair, transcript settlement, the usage batch, queue completion, then the terminal event — in that order, each durable before the next.
4. **Restart.** At launch, a started Turn resumes from its History (ADR-turns-resume-from-an-intent-journal) — counted durably before it relaunches, its reply opening with a resumed notice — and runs past the pause. It repairs as interrupted instead when the user stopped it (Stop, Steer, and edit-last record the stop on the started item before cancelling), when its History is damaged or never got its prompt, or after three resumptions; one whose reply had already ended settles complete without running. A started manual Compaction settles with no record; unstarted work restores paused, with the attended-send grant intact.

## Constraints, state, and failure behavior

- **The queue is durable truth.** Accepted identities dedupe delivery retries; an unreadable queue is retained and blocked, never overwritten; a failed conversation write pauses consumption until repair and reopen.
- **Pause is the user's hand on the wheel**, with exactly two self-clearing paths: the attended-send grant and deleting the last pending item. A queue that settles empty with no queue-level error comes back clean on reload.
- **Compaction never loses context silently**: dividers and notices mark what happened; a compaction summary newer than a goal's stated-objective stamp forces the next continuation to restate it.
- **The transcript never shrinks** except edit-last's and rewind's forward prunes; History and transcript share the chat's persistence lock.
- **A question card is restart-safe by construction** — nothing waits on an RPC; the answer is just the next user message.
- Nothing to compact completes the `/compact` command with a transcript notice and advances the queue without a model request. The notice names the refusing rule (issue #86): no history yet, turns since the last compaction still fit the verbatim tail, or the whole history does — never a bare "nothing to compact".

## Verification

```sh
cargo test -p holt-engine queue
cargo test -p holt-engine compaction
cargo test -p holt-engine title
cargo test -p holt-engine ask_user
cargo test -p holt-engine --test all queue
```

The suites cover admission checkpointing and the edit/delete race window, steer promotion and priority enqueue, the attended-send grant's one-shot scope across a simulated restart, edit-last pruning and identity preservation, compaction triggers (including the overflow retry-once path), the title task's silent failures and answer-rejection, question-card settling and rollback, and restart resume and repair of every started shape. The rewind's plan, staged confirm, and refusal coverage rides the change-set suites (see workspace-git's Verification).
