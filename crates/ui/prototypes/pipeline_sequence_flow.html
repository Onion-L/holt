Diagram 1 — Macro Architecture

宏观拓扑与四条不可逾越的硬边界

Single-Process Headed Architecture
⚡ THE PROBLEM (面临的核心挑战)
  • • 本地状态脆弱性：桌面助手需要直接触碰真实本地文件、Git 仓库和终端 Shell，容易引发意外破坏。
  • • 多轮长程不确定性：大模型流式输出容易遭遇网络中断、429 超限、上下文溢出、幻觉越权。
  • • UI 与执行阻塞耦合：若 UI 直接调用核心业务，长时间工具运行或模型延迟将导致 GPUI 界面假死。
🛡️ THE SOLUTION: Holt 四大硬边界
  • 1. UI ↔ Engine 仅通过 RPC：无直接函数穿透，仅通过 rpc::methods 内存信道传递序列化 ndjson。
  • 2. Engine 是 core 唯一适配器：领域概念（Chat/Session）不侵入通用的 holt-core 代理循环。
  • 3. Git 与文件系统硬隔离：git2 仅在 engine::git，磁盘仅在 engine::files，UI 与 Agent 绝不直碰磁盘。
  • 4. 所有磁盘写入归 Engine 独占原子锁：全量替换写入采用 tmp+rename 原子化，读取容错，持久化安全。

指令分流判别?
(Queue Branch)
Branch 1A: 常规 FIFO Default

先进先出调度头部。标记 Pending → Started，进入主模型处理链路。

Branch 1B: Steer 舵向 Interrupt

取消正在运行的 Turn，等待清理完成后优先执行此指令。

Branch 1C: Edit-Last Prune

仅对最新一条用户消息生效。修剪下游转录与历史，原地替换并重排。

Branch 1D: 暂停例外/压缩 Special

队列暂停时的单次放行特权；或 /compact 仅做压缩不产生 Turn。

Admit Checkpoint Passed

Diagram 4 — Branch Responsibilities Matrix

核心链路各分支职责、触发条件与容错策略

Architecture Invariants
分支分类 分支名称 触发条件 / 场景 核心职责与行为 源码位置 / 关键数据结构 架构决策与 ADR
队列准入分支
(Queue Admission)		 FIFO 常规执行 正常用户连续发送指令 原子转换 Pending → Started，持有单会话执行锁，串行准入 crates/engine/src/queue.rs
Queue::admit_head		 ADR-queue-is-durable-source-of-truth
Steer (舵向打断) 用户在任务执行中点击「插话」或「紧急调整」 下发 CancellationToken 打断当前 Turn，等待资源清理后抢占到队首启动 crates/engine/src/rpc/run.rs
steer_command		 ADR-steer-cancels-and-waits-cleanup
Edit-Last (编辑重发) 用户修改最后一条输入消息 打断当前 Turn，裁切掉该 Turn 之后所有转录与历史，保留消息 ID 就地重新排队 crates/engine/src/rpc/run.rs
edit_last_message		 ADR-edit-last-prunes-forward-only
Attended Send 队列因错误暂停时，用户提交新消息 发放一次性持久化凭证 (attended_grant)，仅允许本条消息越过暂停独立执行 crates/engine/src/queue.rs
attended_grant		 ADR-attended-send-unpauses-one-shot
运行模式分支
(Mode Shaping)		 Plan Mode (计划模式) 用户输入 /plan 或开启计划模式 注入规划系统提示词，剥离所有写与执行工具，仅保留只读探索和 submit_plan crates/engine/src/plan_mode.rs
read_only_tool_allowed		 ADR-plan-mode-is-an-independent-checkpoint
Provider Mode 未配置 Provider 或用户点击配置向导 工具集收敛至网络搜索、模型推荐与 API Key 请求卡，绝不触碰本地代码库 crates/engine/src/provider_mode.rs
create_model_proposal_tool		 ADR-provider-mode-is-a-chat-mode
Subagent (子代理) 模型调用 delegate_subagent 创建子会话运行时，Worker 移除 ask_user，Explorer 保持只读，通过 submit_result 返回 crates/engine/src/subagents.rs
delegation_for_turn		 ADR-subagents-run-nested-turns
权限门禁分支
(Permission Gate)		 只读放行 / Session Grant 非副作用工具（如 read）或已授相同前缀 GateGrants 检查匹配（命令前缀/文件规范路径），命中则标为 Exempted 直接执行 crates/engine/src/gate.rs
is_mutating_tool		 ADR-grants-are-memory-scoped
Auto-Review (模型自审) 权限级别设置为 auto-review 独立开辟单次无工具推理，严格校验回复只有 APPROVE 才放行，任何模糊回答立即拒绝 crates/engine/src/gate.rs
run_review_pass		 ADR-auto-review-fails-closed
Confirm-Changes (人工审批) 默认安全模式下调用写/执行/MCP工具 Turn 挂起，生成 Approval Part。拒绝不崩溃，而是作为 ToolResult::Error 供模型理解并调整路线 crates/engine/src/gate.rs
before_tool_call_hook		 ADR-denials-are-content-not-crashes
传输与容错分支
(Fault Tolerance)		 300s 空闲看门狗 网络僵死，连接保持但连续 5 分钟无任何 token 看门狗超时切断连接，避免 Turn 永久处于 streaming 状态直到应用重启 crates/engine/src/stream.rs
STREAM_IDLE_TIMEOUT		 ADR-idle-watchdog-per-request
In-Turn 溢出恢复 模型在生成前即报 Context Overflow 拒绝请求 就地调用 compact_now 压缩历史并无缝继续当前 Turn，若再次失败则标记下次强制压缩 crates/engine/src/agent.rs
ends_on_rejected_overflow		 ADR-compaction-is-not-a-turn
中断与历史修复 用户点击 Stop 或应用突然退出 repair_history 为所有已启动但未返回的工具补齐合成错误结果，转录标记 Aborted crates/engine/src/history.rs
repair_history		 ADR-turns-resume-from-an-intent-journal
