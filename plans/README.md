## Parallel execution protocol (3 clean sessions)

Run each plan in its own session, each rooted in its own git worktree so the
main checkout is never touched mid-flight:

```bash
cd /Users/onion/workbench/holt
git worktree add ../holt-w001 -b refactor/001-split-appearance 5c2f3f4
git worktree add ../holt-w002 -b refactor/002-split-engine     5c2f3f4
git worktree add ../holt-w003 -b refactor/003-split-shell      5c2f3f4
```

In each worktree, share the main repo's build cache (each worktree would
otherwise recompile the vendored gpui tree from scratch):

```bash
cd ../holt-w00N
export CARGO_TARGET_DIR=/Users/onion/workbench/holt/target
```

Concurrent `cargo` invocations across worktrees serialize on the shared
target-dir lock — waiting is expected, not a failure.

Recommended merge order (any order works; this is smallest-first):
**001 → 002 → 003**. After merging each branch into `main`, rebase the
remaining worktrees (`git -C ../holt-w00N rebase main`) — for these disjoint
edit sets the rebase is a fast-forward of context, with no conflicts expected.

Alternative — a single orchestrating session dispatching executor subagents —
works too, but each plan moves 1500–2500 lines and is safer in a session with
full context than in a subagent. Prefer the 3-session protocol.

## Review gate — MANDATORY before every commit

Every plan ends each step with a commit. Do NOT run `git commit` until the
gate passes:

1. **Machine checks** (exact commands are in each plan):
   `cargo fmt -p <pkgs> -- --check`, `cargo clippy --workspace`,
   `cargo test --workspace` — all clean, test counts at baseline.
2. **Scope check**: `git add -A && git diff --cached --stat` lists ONLY files
   in that plan's In-scope list.
3. **Move check**: `git diff --cached --color-moved=dimmed-zebra` — for
   pure-move commits nearly every hunk must render as moved blocks. Any hunk
   that is not moved-colored must be one of: new `mod`/`use` wiring, a
   visibility keyword, a module doc header, or (plan 001, commit 4 only) the
   documented extraction.
4. **Independent review**: dispatch a fresh-context reviewer subagent (or a
   second session) with the plan's move manifest and the review prompt
   embedded in each plan. Commit only on PASS. If no reviewer is available,
   self-review against the same checklist and note `(self-reviewed)` in the
   commit body.

Commit message style (from `git log`): `refactor(ui): split the appearance
settings page into a module directory`, `refactor(engine): …`,
`refactor(ui): …`. Do NOT push or merge to `main` from an executor session
unless the operator instructed it — the operator merges.

```text
You are reviewing a staged pure-move refactor commit. Working tree: <worktree
path>. Plan file: plans/NNN-<slug>.md — read its Scope section, its move
manifest(s), and the step whose commit is under review. The diff to review is
`git diff --cached` in that worktree. Verify, then reply PASS or FAIL with a
numbered finding list:
1. Only files listed in the plan's "In scope" are staged.
2. Every hunk traces to the step's move manifest or to wiring the plan
   explicitly allows (mod/use lines, listed visibility keywords, module doc
   headers, relocated tests).
3. Moved code is verbatim: no renames, no changed expressions/strings, no
   comment edits inside moved bodies (new //! module headers are allowed).
4. No out-of-scope change snuck in (unrelated formatting, "quick fixes", the
   known composer/send_mode.rs:118 unused import).
5. The executor's last fmt/clippy/test output shows the baseline numbers
   (525 ui / 24 engine, clippy exit 0) — ask for it if not attached.
Treat any ambiguity as FAIL with a question, not a guess.
```
